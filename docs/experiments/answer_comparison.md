# Qwen 端到端答案对照

本实验验证相同 Qwen 生成模型在 Hybrid+Page 与 Hybrid+Table+Page 证据下的答案表现。
检索覆盖率与答案正确率分别统计，不能用前者替代后者。

## 冻结的输入与方法

- 42 道 Explicit Eval：34 道已绑定 Gold 的可回答题、8 道真实跨知识库负例。
- Gold SHA-256：`f7f1151f4a0b2733d5b2d133d3f7fbbd9d5105a3eb373873ac33bd330bbf8596`。
- 30 条表格事实 SHA-256：`cde3b8952ffe787d064e1ed404ba62f275f260632ea9483648bb80f4ea14d4b9`。
- 索引 1440 块；正文、ID、元数据摘要：`a4bd0d2b56c471fcee13fbda928008477aa4b546d8b855be41097ac715fb9228`。
- 两方案均取 Top-3，并采用 1 页、新增最多 12 块、新增最多 2500 字符的同页扩展。
- 生成：`qwen3.7-flash-2026-07-15`，温度 0、最多 2048 tokens、显式关闭思考模式。
- 评委：`qwen-plus`，温度 0、最多 2048 tokens。模型别名背后的服务版本可能随厂商更新。
- 按题交替运行两方法，不修改 GUI、Gold、表格事实或检索参数。

生成模型只收到问题、真实上下文与本轮引用编号，不接收参考答案和 Gold。
Qwen3 的思考开关只作用于评测调用，使用
[官方 API 参数](https://www.alibabacloud.com/help/zh/model-studio/deep-thinking)，不改应用模型配置。

## 评分口径

质量评委调用使用参考答案、必需事实和实际证据，输出正确性、每个事实是否表达、忠实性和负例拒答。
不同事实为 AND；同一事实的原文备选为 OR。事实完整性先按题计算覆盖比例，再宏平均。
正确表达必需事实后，额外且受原文支持的说明不应造成完整性扣分。

引用核验采用独立调用，只看问题、实际证据、生成答案与引用编号，不看参考答案或 Gold。
编号合法不代表内容支持：应检查该编号支持的全部实质断言及文件、版本、页码归属。
引用准确性按每道 Gold 答案的有效引用比例宏平均；Gold 答案没有引用时记 0。
真实负例只参与拒答分母，未绑定 Gold 的题不能算作负例或混入答案正确率分母。

每项分数均记录 `n`。模型调用失败、空回答、截断、评委 JSON 不合法分别保存错误，
不把这些失败悄悄计成 0 或忽略错误计数。端到端延迟包含检索、同页扩展和生成，
不含离线评委及模型初始化。实际 token usage、结束原因和评委原文随逐题记录保存。

自动评委不是人工真值，两个模型同属 Qwen 系列，仍可能有一致偏差。
两份手册和两张表在 Dev/Eval 间共享，因此不是跨文档泛化评测。

## 开发校准记录

使用 Dev 的安装方式/文件系统、快捷键、运行级别和跨知识库负例检查调用链路。
抽查发现早期评委会把有证据支持的补充说明误当成错误引用，或把合理拒答判为不忠实。
因此将引用核验与答案质量评分分开，并明确“事实已正确表达”不因冗余说明变为未覆盖。
校准只使用 Dev 样例，正式完成后的 Eval 错题不用于继续修改口径。

早期试运行因空回答中止，3 条部分记录、当时代码及 Dev 校准/冒烟记录已压缩保存在
`results/answer_eval_explicit/development_audit.zip`，不计入正式结果。
归档保留原目录结构和文件 SHA-256 清单，并经逐文件还原校验；临时目录已移除。
当前冻结协议为 `protocol_version=4`，正式运行单独使用 `results/answer_eval_explicit/`。
这些版本是答案评测器的开发校准，原始独立检索 Eval 的结果和输入保持不变。

84 条方法×题目记录已全部完成；正确性、完整性和引用指标各使用 34 道 Gold，

| 答案事实完整性 | 76.47% | 91.18% |
| 引用准确性（逐答案宏平均） | 94.61% | 98.53% |
| 引用编号合法率 | 100% | 100% |
| 真实负例拒答率 | 100%（8/8） | 100%（8/8） |
| 忠实性（42 题宏平均） | 97.86% | 96.19% |
| P95 检索+扩展+生成 | 7.834 秒 | 4.320 秒 |
| 知识库泄漏题数 | 0 | 0 |

答案正确性和完整性各改善 5 题、退步 0 题、持平 29 题；改善题为
`ENT-SHORT-0007`、`ENT-SHORT-0014`、`ENT-SHORT-0019`、`ENT-PARAP-0032`、`ENT-PARAP-0044`。
这些题在基线证据不足时拒答，加入表格路径后能够回答相应快捷键。
引用准确性改善 3 题、退步 0 题、持平 31 题。
单轮远程模型调用受服务端波动影响，P95 差异不能归因为 Table 检索本身更快。

一次质量评委把 Gold 可回答题的 `abstained` 返回为 true，触发格式校验失败。
保留答案、使用完全相同参数续跑后成功；没有重新生成该答案。
最终未解决的生成/评分失败均为 0，重试事件另见 `retry_diagnostics.json`。
回归测试 173 项通过、1 项跳过。`verification.json` 核验了全部 84 条记录的实际原文、页码、
知识库范围和生成提示；检索 Chunk ID、事实覆盖及 MRR 与上一轮独立检索 Eval 完全一致，
Gold、表格事实、既有报告和索引正文/元数据指纹均未改变。

## 待复核的评分与生成问题

- `ENT-FAQ-0004`、`ENT-PARAP-0004`：评委仍疑似过度要求逐字复述来源锚点，
  甚至将通用占位描述“来源原文证据”当作需要回答的内容。这两题的正确性/完整性评分需人工核查。
- `ENT-FAQ-0017`：两方案都否定“直接运行原生 Windows 游戏”，参考答案描述软件中心可安装游戏。
  需要核对问题、参考答案和生成断言的语义范围，不能直接把自动扣分视为人工真值。
- `ENT-SHORT-0019`：增强方案答出 Print，但还引用了页眉和其他快捷键分块，
  自动引用准确性仅为 50%。正确证据已进入上下文，仍可能出现引用选择错误。
- 忠实性自动评分略降；不据此宣称所有生成质量指标都提升。

`review_pending.jsonl` 汇集 8 道两方案任一答案正确性或引用评分未满分的题，
同时保留参考答案、Gold 锚点、两方案答案及实际证据；人工评分字段仍为空。
本轮不覆盖自动原始评分，不修改 Gold、表格事实或评分规则。
