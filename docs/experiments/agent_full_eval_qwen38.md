## 评分含义与验证范围

本轮使用真实 Qwen 生成可见 ReAct 文本和工具 Action，并经过真实的
Registry → Pydantic → Executor → 审批票据 → Trace 链路。
底层 41 个工具全部为模拟 handler；`create_text_file` 也只替换物理写入，不在本机创建业务文件。
删除、关机、终止进程、Shell、浏览器、邮件和缓存清理均未真实执行。
报告生成工具在本轮返回合成报告，没有额外调用业务分析模型。

审批决定由脚本按题集固定批准或拒绝。31/31 表示系统在模拟拒绝后没有执行 handler，
不能解释为模型独立判断危险请求的拒绝正确率，也不替代真实 Qt 人工点击验收。

严格规则要求预期工具序列、规范化参数、模拟调用和审批分支全部一致，
有非空最终回答且无 Agent 错误。`arguments_correct` 比较整段步骤及参数，
不是只看 Pydantic 类型是否有效；无需工具题只要求正常回复且没有 Action。
最终答案尚未逐题语义评分，因此 100% 是本固定场景集的规则通过率，
不能写成真实系统任务成功率或所有业务答案正确率。3 并发 P95 包含网络与服务端影响，
不等同于单用户 GUI 延迟。
