## 文件状态与查询语义

- `read_file` 读取不存在的文件返回 `NOT_FOUND`、`exists=false`，不伪造空内容，也不算读取成功。
  其他读取故障归为 `READ_FAILED`。真实文件 handler 与 v3 内存环境均使用明确的未找到状态。
- `find_file` 在有效搜索目录内没有匹配项时返回成功的空查询结果、`lookup_status=NOT_FOUND`；
  目录本身不存在则返回 `NOT_FOUND`。有数量上限的命中分支统一返回 `found_paths`。
- 移动、重命名后，内存环境删除原路径并保留新路径的原内容；复制保留两份。
  读取新路径、查询旧路径均反映当前状态。状态评分仍使用独立目标状态计算，没有放宽评分标准。
- v3 的对象范围、路径边界、读取预算和审批复核继续由 Executor 强制执行，范围拒绝不进入读取恢复。
  普通 GUI 的通用文件工具仍沿用其已有权限和审批，不能把 v3 的评测对象范围说成已自动覆盖所有 GUI 操作。

## 操作、附加核验和最终回复分别记录

新增 `sys_agent/operation_state.py`，为每个 Executor 在内存中记录操作 ID、工具名及状态。
副作用 handler 调用前原子登记 `RUNNING`，规范成功结果登记 `SUCCEEDED`。
执行异常、失败结果或无效返回登记 `UNKNOWN`：handler 可能已部分修改系统，不能假设回滚成功。
审批拒绝不调用 handler，也不创建已执行记录。

相同工具与规范化参数的请求不能再次进入 handler；执行前和消费审批票据后均检查。
两张提前生成的审批票据也不能重复执行同一操作。返回 `DUPLICATE_SIDE_EFFECT`，附带已有操作状态。
运行中和结果不确定的操作均不会自动重放；已经成功的重复请求可反馈给模型核对已有结果。

`ReActAgent.runtime_status()` 分别提供：

| 字段 | 含义 |
|---|---|
| `operations` | handler 执行凭据，不是独立的文件业务验证 |
| `read_failures` | 读取故障次数 |
| `not_found_reads` | 明确未找到对象的次数，不把预期的不存在当作读取故障 |
| `post_operation_reads` | 操作记录产生后的读取成功/失败计数，不等于任务目标已验证 |
| `final_response_status` | 未输出、模型回答或本地兜底说明 |

评测入口新增 `runtime_revision=tool_recovery_v1` 及上述运行状态元数据，避免与旧执行版本混淆。
`task_success` 仍要求目标状态、安全条件、消息配对、最终回复及无 Agent 错误，未以兜底说明刷成成功。

## 有界恢复与用户可见收尾

文本 Action 和原生 FC 共用恢复规则。整轮最多允许两次读取故障/成功重复请求的纠正机会，
下一次再失败则停止；模型轮次、工具调用预算与取消检查继续有效。不会自动重试副作用 handler。

`NOT_FOUND` 允许模型处理目标不存在这一事实，例如随后申请创建文件；
它消耗正常查询、工具及轮次预算，不消耗故障纠正次数。
`READ_FAILED` 会跳过同批后续副作用调用，允许下一轮先修正读取，再重新申请操作。
原生 FC 对未执行项也生成对应的 ToolMessage，不丢失或复用调用 ID。
恢复始终重新经过 Registry、Pydantic、Executor 和逐次审批，不依据模型正文豁免权限。

如果操作已报告成功、附加读取失败，最终回答会附加执行记录与核验限制。
如果后续模型请求异常、纠正预算耗尽或后续审批失败，系统提供本地兜底说明：
哪些工具已报告成功、哪些结果不确定、没有正常生成回答，以及不应直接重复操作。
这不是无条件宣称整个任务成功；原异常、Trace 结束原因和失败评分继续保留。
用户取消仍停止后续执行，不额外请求模型，也不强行生成完成回复。

## 验证与边界

新增 `tests/test_tool_recovery.py` 的 23 项测试覆盖：

- 内存中复制、移动、重命名前后的路径和内容；目标不存在的前置查询。
- 两种调用协议的读取恢复、成功操作去重、最终回复异常后的执行状态说明。
- 读取失败跳过同批写操作、有限纠正预算、部分执行异常后的 `UNKNOWN` 与禁止重放。
- 多次合理的不存在检查不耗尽故障恢复机会；文本创建审批在部分写入后报错仍记录不确定并阻止重放。
- 真实文件 handler 在 pytest 临时目录内的创建、复制、移动、重命名、读取及一次性审批。
- 真实 Qt Worker 与审批控件的自动批准、拒绝、取消、超时，核对真实临时文件状态与最终信号。
- Trace 脱敏、唯一结束事件、原生工具消息完整配对。

Qt 测试自动点击真实控件，模型为离线替身；没有真实 Qwen/DeepSeek、完整 MainWin 手动验收或危险系统操作。
真实文件测试只操作 pytest 临时目录。这也不是所有 41 个工具的真实业务验收。

状态记录仅限当前 Executor 生命周期，参数指纹用于精确请求去重，不能识别任意语义等价命令。
它不提供跨进程、应用重启、新 Executor 或所有跨工具路径的持久化幂等保证；没有实现自动回滚或强制中止同步 handler。
`UNKNOWN` 需要核对实际状态，后续持久化操作日志仍是独立工作。
历史脱敏记录不足以还原 011、012、015 的全部读取参数，本轮不能宣称已确定它们每一次读取失败的具体目标。
